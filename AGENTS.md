# AGENTS.md — правила работы в Zaruba

Файл для агента (Cline, Copilot, Cursor) и для человека: правила одни и те же.
Нарушенное правило — повод не принять правку, а не «обсудить в чате».

## Проект

- Неофициальный фан-сайт чемпионата «ЗАРУБА» (Тюмень): FastAPI + Jinja2,
  контент в `content/*.yaml`, базы данных и JS-логина нет.
- Источник истины — `docs/06-info-section.md` (§6.5 — фото, §6.11 — портреты
  жюри, §6.22 — приёмка). Код следует спецификации; расхождение — повод править
  документ вместе с кодом, а не «как получилось».
- Факт без источника не публикуется: либо его нет на странице, либо он с явной
  пометкой и ссылкой на первоисточник.

## Запрещено

- Менять тесты, чтобы они прошли; понижать `fail_under` (90 %); ставить
  `# noqa` или `type: ignore` без объяснения рядом.
- Добавлять зависимости и править `requirements*.lock` руками: лок собирает
  `uv pip compile`, CI проверяет расхождение.
- Выдумывать данные — номинации, имена, суммы, тайминг, фото. Нет данных —
  пустое состояние с объяснением, а не «примерно».
- Ставить чужое фото без основания: только `use: citation` (ст. 1274 ГК РФ:
  цель + автор + источник) или разрешение автора.
- Рефакторить то, о чём не просили: правка больше 60 строк или 6 файлов
  дробится на шаги.
- Коммитить `.env`, секреты и `assets/photos/*` — исходники фото живут вне git.

## Шаг работы

1. **Спека** — 5 строк: что появляется, контракт (вход, выход, исключения),
   что НЕ делаем, критерий готовности.
2. **Ветка** `feat/…`, `fix/…`, `chore/…`: в `main` только слиянием.
3. **Красный тест** — падает по нужной причине, а не из-за опечатки.
4. **Минимальный код** до зелёного, без «заодно».
5. **Проверки** — весь список ниже.
6. **Коммит**: `<тип>: <что>` (типы: feat, fix, test, docs, chore, style,
   refactor), в теле — почему и строка `Проверено: …`.
7. **Отчёт**: `Изменил` / `Проверил` / `Не сделал`.

## Проверки перед отчётом

Из активированного `.venv`:

```powershell
python -m pytest -q --cov=zaruba --cov-report=term-missing
python -m ruff check src tests
python -m ruff format --check src tests
python -m mypy
python -m zaruba.content check
python tools/check_md_tables.py; python tools/check_md_chars.py; python tools/check_html.py
```

`pre-commit install` уже выполнен: `git commit` сам гоняет ruff, проверку
контента и документов. CI повторяет это на Ubuntu, плюс `bash -n deploy/smoke.sh`,
`pip-audit` и сборку образа.

## Где что лежит

| Путь | Что | Правило |
|---|---|---|
| `src/zaruba/routers/` | HTTP-слой | собрать данные и отрендерить, без логики |
| `src/zaruba/services/` | логика | не знает про `Request`, тестируется без клиента |
| `src/zaruba/models.py` | схемы YAML | `Strict`: лишнее поле — ошибка, а не мелочь |
| `src/zaruba/content.py` | загрузка и валидация | ошибка называет файл и поле |
| `src/zaruba/templating.py` | фильтры Jinja | чистые функции и тест на каждый |
| `src/zaruba/templates/` | Jinja2 | без JS-логики, пустые состояния обязательны |
| `content/` | данные | только подтверждённые факты |
| `tests/` | pytest | файл на модуль, имя по модулю |
| `tools/` | офлайн-скрипты | приложение их не импортирует |
| `docs/` | спецификация | правится вместе с поведением сайта |

## Стиль

- ruff: `line-length = 100`, набор `E, F, I, UP, B, SIM`; mypy:
  `disallow_untyped_defs`, `check_untyped_defs`.
- Аннотации обязательны, `from __future__ import annotations` в каждом модуле.
- Комментарий объясняет **почему** решение такое, а не пересказывает код.
- Новое поле в YAML — это три правки: модель, загрузчик, тест. Без теста поле
  не считается добавленным.

## Готово, когда

- все проверки зелёные, дерево чистое;
- покрытие не ниже 90 %, новые ветки логики покрыты тестом;
- в отчёте сказано, что осталось несделанным и почему;
- если правило пришлось повторить дважды — оно дописано сюда.
