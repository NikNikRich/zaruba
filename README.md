«ЗАРУБА DANCE CHAMP»** (Тюмень). Живёт в собственной папке
`C:\well-service-platform\Zaruba` — отдельно от сервиса по ГОСТ 31371.7
(`VS 001`), чтобы не путать контексты, зависимости и данные.

## Решения, которые уже зафиксированы

- **Сайт делает фанат**, а не организатор: не продаём билеты, не принимаем
  деньги, не выглядим официальными, домен — без слова «заруба».
- **Первым делаем информационный блок** (`06`), интерактив (`05`) — поверх
  готовых данных.
- Стек — как в прежнем проекте: **FastAPI + Jinja2**, pytest, ruff. SPA нет,
  JS-логина нет, инфо-страницы работают без JS вообще.
- **Базы данных нет**: контент — YAML в `content/`, читается и валидируется на
  старте. SQLAlchemy, Alembic и Redis появятся только вместе с интерактивом
  (`docs/05`), когда возникнут голоса, дуэли и пользовательские данные.
- Пакет `src/zaruba/` — отдельный, не внутри чужого `src/app`.
- Каждый факт на сайте — со **статусом источника** (`подтверждено` /
  `не подтверждено` / `устарело`); для несовершеннолетних без согласия —
  инициалы, без фото, `noindex`.

## Запуск сайта

```powershell
cd C:\well-service-platform\Zaruba
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m uvicorn zaruba.main:app --reload --port 8000
```
Настройки читаются из окружения с префиксом `ZARUBA_` (см. `.env.example`). Раздел
`/ratings` по умолчанию закрыт: пока нет протоколов и голосования, он объясняет методику
и отдаёт `noindex`; включить публичный режим — `ZARUBA_RATINGS_ENABLED=true`.



Страницы: `/` (главная), `/event` (о событии и хронология), `/history` (архив по годам),
`/ratings` (рейтинги и методика v1 — за флагом `ZARUBA_RATINGS_ENABLED`), `/schedule`
(расписание, `?day=1`), `/performances` (каталог с фильтрами `?day=&style=&age=&format=&studio=&video=1`),
`/performances/{slug}` (карточка выступления), `/participants` (каталог участников с
`?q=&studio=&city=&age=&style=`), `/participants/{slug}` (карточка участника),
`/studios` и `/studios/{slug}` (студии и их составы), `/judges` (жюри и критерии),
`/tickets` (билеты без продаж), `/glossary` (направления и термины), `/faq` (12 вопросов),
`/search?q=` (поиск по участникам, выступлениям, номинациям, студиям и глоссарию),
`/venue` (площадка), `/about` (о проекте), `/rules` (регламент и правила сайта),
`/privacy` (данные), `/takedown` (удаление за 48 часов), `/healthz` (состояние). Шаблоны —
серверный рендер: все факты видны при
выключенном JS; неизвестный адрес отдаёт HTML-страницу 404 с выходами, а неверный
фильтр (`?day=9`, `?age=abc`) — страницу 422 с объяснением, какой параметр не подошёл.
Для роботов: `/robots.txt` и `/sitemap.xml` — только подтверждённые страницы, демо-записи
и карточки несовершеннолетних без согласия в sitemap не попадают; JSON-LD (`Event`,
`BreadcrumbList`, `FAQPage`, `DefinedTermSet`) собирается в `services/seo.py`, `Person`
не размечается ни для кого.

```powershell
.\.venv\Scripts\python.exe -m pytest -q             # тесты
.\.venv\Scripts\python.exe -m pytest -q --cov=zaruba  # тесты + покрытие (порог 90 %)
.\.venv\Scripts\python.exe -m ruff check src tests   # линт
.\.venv\Scripts\python.exe -m mypy                   # типы
.\.venv\Scripts\python.exe -m zaruba.content check   # проверить YAML выпусков
.\.venv\Scripts\python.exe -m zaruba.content import content\editions\2025.yaml
```

Хуки и лок зависимостей:

```powershell
.\.venv\Scripts\python.exe -m pre_commit install    # один раз: проверки перед коммитом
.\.venv\Scripts\python.exe -m pre_commit run --all-files

# после правки pyproject.toml — пересобрать лок (то же проверяет CI)
.\.venv\Scripts\python.exe -m uv pip compile --universal -o requirements.lock pyproject.toml
.\.venv\Scripts\python.exe -m uv pip compile --universal --extra dev -o requirements-dev.lock pyproject.toml
```

Лок кросс-платформенный: `uv --universal` оставляет `uvloop` с маркером для Linux,
поэтому набор из Windows совпадает с тем, что ставится в образ и в CI.

Правила контента (проверяются тестами, а не «на глаз»):

- любое поле сверх модели — ошибка, опечатка в YAML не теряется молча;
- блок обязан ссылаться на существующие номинации того же дня;
- выступление ссылается на существующую номинацию, участников и дату выпуска;
- судья ссылается на существующий блок, а термин глоссария — на стиль из справочника;
- у несовершеннолетнего без согласия публичное имя — только инициалы;
- демонстрационные строки помечены `demo: true` и показываются как «пример»;
- FAQ без источника помечается статусом «не подтверждено», а не подаётся как факт.

## Публикация

Прод — тот же uvicorn за обратным прокси: приложение не умеет TLS и не должно.

```powershell
Copy-Item .env.example .env          # ZARUBA_ENV=prod, флаги, FORWARDED_ALLOW_IPS
docker compose up -d --build
curl http://127.0.0.1:8000/healthz
```

Что важно именно для этого проекта:

- `--proxy-headers` (в образе уже включён) и `X-Forwarded-Proto` от прокси: без них
  canonical, `robots.txt` и `sitemap.xml` отдают `http://127.0.0.1:8000`.
- `--limit-concurrency 64` (Dockerfile и юнит systemd): сверх потолка uvicorn сразу
  отвечает 503, а не копит соединения в памяти — процесс один, воркеров нет.
- `X-Request-ID` есть на каждом ответе и на странице сбоя: номер приходит от прокси
  (`proxy_set_header X-Request-ID $request_id`) или генерируется приложением, он же
  попадает в журнал. По нему находят запись, если посетитель сообщил о сбое.
- `ZARUBA_ENV=prod` включает HSTS; CSP, `nosniff`, `X-Frame-Options` и
  `Referrer-Policy` отдаются всегда (`middleware.py`), `/static` кэшируется на час.
- `content/` монтируется в контейнер только на чтение: правка YAML — рестарт,
  а не пересборка образа.
- Сжатие и кэш статики — в `deploy/nginx.conf.example`; юнит `deploy/zaruba.service` —
  для установки без Docker.
- Перед выкладкой: `python -m zaruba.content check` и `python -m pytest -q` — то же
  делает CI; он же проверяет типы (`mypy`), покрытие (порог 90 %), уязвимости
  (`pip-audit` по `requirements.lock`), свежесть лока, собирает образ и проверяет
  `/healthz`, `/privacy`, CSP и проброс `X-Request-ID`.
- Бэкап: `content/*.yaml` — единственный источник фактов; `.env` не коммитится.

Чего в деплое нет намеренно: базы данных (контент — YAML), фоновых задач и Redis.

## Чего не хватает (блокеры данных)

Официальное «Положение» выпуска **12–13 декабря 2026** получено 23.10.2026:
в `docs/01-research.md` §1.6 теперь есть даты, площадка, 15 номинаций с
возрастами, взносы, зрительские билеты, критерии, хронометраж, жюри и
мастер-классы. Остались блокеры, которые документ не закрывает:

- **Тайминг блоков** 12–13 декабря: в «Положении» есть только «1 блок» и
  «2 блок», без времени начала. Поэтому `/schedule` показывает номинации по дням
  и точное время мастер-классов, но не выдуманную сетку.
- **Списки участников, команд и студий 2026**: регистрация открыта до
  07.12.2026, публикаций ещё не было. Каталоги `/performances` и `/participants`
  показывают архив 2025 с явной пометкой «Это архив 2025 года», а не пустую
  страницу и не прошлогодние пары под видом 2026-го.
- **Призовой фонд по номинациям**: в PDF таблица теряет структуру при извлечении,
  поэтому суммы на сайте не публикуются.
- **Результаты и рейтинги прошлых лет**: судейские протоколы не публикуются.
- **Telegram и MAX недоступны машинно** (t.me — ошибка сети, tgstat — 403):
  посты канала `@zaruba72champ` собираются вручную.
- **Права на бренд и домен**: домен сайта не должен содержать «заруба»;
  вопросы к организаторам об использовании названия и логотипа открыты.
- **Команда организаторов, партнёры и тренеры студий** публично описаны только
  как «студия „Печать танца“, Оксана Бабкина, Алина Богданова» — поэтому
  страницы `/organizers` и карточки тренеров не сделаны.

Правило проекта: неподтверждённый факт **не выдумывается** — он либо не
показывается, либо показывается с явной пометкой и ссылкой на первоисточник.
