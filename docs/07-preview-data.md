# 07. Данные для показа: таблицы, overlay и пометка «пример»

> Презентационный слой поверх опубликованного выпуска. Он нужен, чтобы показать
> заполненные страницы до появления реальных заявок, и не нарушать правило
> проекта: **выдуманный факт не живёт в базовом YAML**. Всё, чего нет в
> «Положении» и официальных постах, лежит в `content/editions/2026.d/` и
> подмешивается только при `ZARUBA_PREVIEW_ENABLED=1`.

## 7.1. Из чего состоит

| Что | Путь | Правило |
|---|---|---|
| Таблицы для заполнения | `docs/templates/*.csv` | одна строка — одна сущность модели; `;`, UTF-8 с BOM (открывается в Excel) |
| Генератор overlay | `src/zaruba/sync_tables.py` | читает таблицы, сверяет `real`, пишет YAML |
| Презентационный слой | `content/editions/2026.d/*.yaml` | в git лежит только то, что помечено `preview`; удаляется одной командой |
| Публичные факты | `content/editions/2026.yaml` | правится вручную по источнику, таблицей не перезаписывается |

Overlay — не второй выпуск: загрузчик `merge_overlay` дополняет базовый YAML
строками из `*.d/*.yaml`. Совпадение по `slug` — точечный патч: меняются только
переданные поля. Так тайминг номинации добавляется, не трогая подтверждённые
название, возраст и источник.

## 7.2. Тег `data_tag`

| Тег | Что значит | Что делает скрипт |
|---|---|---|
| `real` | факт уже опубликован в `content/editions/2026.yaml` | только сверяет: любое расхождение по полю — ошибка с именем поля |
| `preview` | демонстрационные данные | пишет в overlay и ставит `demo: true` всем моделям, у которых есть это поле |

`real`-строки — зеркало, а не путь записи. Подтверждённый факт меняется в
базовом YAML (и в источнике), после чего таблица обновляется под него. Пустая
клетка оставляет значение модели по умолчанию.

## 7.3. Колонки таблиц

| Файл | Колонки |
|---|---|
| `studios.csv` | `slug`, `name`, `city`, `vk_url`, `demo`, `data_tag` |
| `participants.csv` | `slug`, `display_name`, `age_group`, `studio`, `city`, `consent_status`, `consent_at`, `demo`, `data_tag` |
| `blocks.csv` | `slug`, `day`, `title`, `starts_at`, `ends_at`, `stage`, `nominations`, `note`, `data_tag` |
| `performances.csv` | `slug`, `title`, `nomination`, `participants`, `scheduled_at`, `order_no`, `stage`, `status`, `video_url`, `source_id`, `demo`, `data_tag` |
| `nominations.csv` | `slug`, `name`, `style`, `format`, `age_group`, `levels`, `min_participants`, `max_participants`, `day`, `starts_at`, `ends_at`, `stage`, `status`, `note`, `source_id`, `demo`, `data_tag` |
| `judges.csv` | `slug`, `name`, `role`, `city`, `regalia`, `styles`, `blocks`, `source_id`, `photo`, `photo_author`, `photo_license`, `photo_use`, `photo_purpose`, `photo_source_url`, `photo_nature`, `demo`, `data_tag` |

Списки (`levels`, `nominations`, `participants`, `styles`, `blocks`) пишутся
через `|` (запятая тоже принимается). Время — `ЧЧ:ММ`, дата-время —
ISO 8601 с часовым поясом (`2026-12-12T10:00:00+05:00`). Шапка проверяется
целиком: лишняя или пропущенная колонка — ошибка, а не «мелочь».

Для несовершеннолетних `display_name` — инициалы (`Л. В.`), для 18+ допустимо
полное имя. Это проверяет модель `Participant`, а не только скрипт.

## 7.4. Тайминг номинаций

В «Положении» времени начала нет. Скрипт выводит границы номинации из её
выступлений внутри блока:

1. блок задаёт окно `starts_at`–`ends_at` и список номинаций;
2. выступления дают моменты `scheduled_at`;
3. начало номинации — первый момент (не раньше начала блока), конец — последний
   момент + 10 минут (не позже конца блока).

Если у номинации нет выступлений, момент вне блока или окно пустое — импорт
падает с сообщением, а не пишет «примерно». Патч содержит только `slug`,
`starts_at`, `ends_at`; всё остальное берётся из опубликованного YAML.

## 7.5. Порядок работы

```powershell
# 1. Проверить таблицы и overlay, ничего не записывая
.\.venv\Scripts\python.exe -m zaruba.sync_tables --check

# 2. Собрать overlay (перезаписывает только разделы из таблиц)
.\.venv\Scripts\python.exe -m zaruba.sync_tables

# 3. Посмотреть сайт в режиме предпросмотра
$env:ZARUBA_PREVIEW_ENABLED = "1"
.\.venv\Scripts\python.exe -m uvicorn zaruba.main:app --reload --port 8000

# 4. Убрать все презентационные строки одной командой
.\.venv\Scripts\python.exe -m zaruba.sync_tables --drop-preview
```

`--check` сверяет не только таблицы, но и уже записанный overlay: устаревший или
лишний файл — ошибка, чтобы показанные страницы не разошлись с таблицами.
`--drop-preview` удаляет только overlay: CSV-таблицы остаются рабочим материалом для
следующего показа, а базовый YAML не меняется вовсе. Чтобы вернуть примеры,
достаточно снова выполнить `python -m zaruba.sync_tables`.

Без флага `ZARUBA_PREVIEW_ENABLED` сайт работает на подтверждённых фактах, а
`content/editions/2026.d/` не читается вовсе. С флагом:

- в шапке страницы появляется пометка «предпросмотр»;
- все страницы получают `noindex, nofollow` — даже если роутер передал другой
  `robots`;
- на расписании и главной вместо «тайминг не опубликован» выводится
  объяснение, что блоки демонстрационные.

Флаг не заменяет приёмку: перед публикацией `--drop-preview`, затем
`pytest`, `zaruba.content check`, `ruff`, `mypy` — по `AGENTS.md`.

## 7.6. Чего здесь нет

- **Фото, видео и ссылок на соцсети участников** — только подтверждённые
  источники; выдуманное фото нельзя ставить даже с пометкой.
- **XLSX** — в зависимостях нет `openpyxl`, а лок заморожен; формат CSV
  открывается в Excel и не требует новой библиотеки.
- **Записи `real` из таблицы** — намеренно, чтобы импорт не мог подменить
  опубликованный факт.
