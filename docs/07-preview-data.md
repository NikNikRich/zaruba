# 07. Данные для показа: таблицы, overlay и пометка «пример»

> Презентационный слой поверх опубликованного выпуска. Он нужен, чтобы показать
> заполненные страницы до появления реальных заявок, и не нарушать правило
> проекта: **выдуманный факт не живёт в базовом YAML**. Всё, чего нет в
> «Положении» и официальных постах, лежит в `content/editions/2026.d/` и
> подмешивается только при `ZARUBA_PREVIEW_ENABLED=1`. Рекламные примеры лежат
> отдельно — в `content/offers.preview.yaml`: боевой `content/offers.yaml`
> остаётся пустым, а выдуманный `erid` не попадает в публичный контент.

## 7.1. Из чего состоит

| Что | Путь | Правило |
|---|---|---|
| Таблицы для заполнения | `docs/templates/*.csv` | одна строка — одна сущность модели; `;` или `,` (выгрузка Google), UTF-8 (с BOM или без) либо cp1251 |
| Генератор overlay | `src/zaruba/sync_tables.py` | читает таблицы (локальные или из Google Таблиц), сверяет `real`, пишет YAML |
| Презентационный слой | `content/editions/2026.d/*.yaml` | в git лежит только то, что помечено `preview`; удаляется одной командой |
| Демонстрационные офферы | `content/offers.preview.yaml` | два примера нативных вставок; читаются только при `ZARUBA_PREVIEW_ENABLED=1` и только если в `content/offers.yaml` нет действующего оффера слота |
| Публичные факты | `content/editions/2026.yaml` | правится вручную по источнику, таблицей не перезаписывается |

Overlay — не второй выпуск: загрузчик `merge_overlay` дополняет базовый YAML
строками из `*.d/*.yaml`. Совпадение по `slug` — точечный патч: меняются только
переданные поля. Так тайминг номинации добавляется, не трогая подтверждённые
название, возраст и источник.

## 7.2. Тег `data_tag`

| Тег | Что значит | Что делает скрипт |
|---|---|---|
| `real` | факт уже опубликован в `content/editions/2026.yaml` | только сверяет: любое расхождение по полю — ошибка с именем поля |
| `preview` | демонстрационные данные | пишет в overlay и ставит `demo: true` всем моделям, у которых есть это поле |

`real`-строки — зеркало, а не путь записи. Подтверждённый факт меняется в
базовом YAML (и в источнике), после чего таблица обновляется под него. Пустая
клетка оставляет значение модели по умолчанию.

## 7.3. Колонки таблиц

| Файл | Колонки |
|---|---|
| `studios.csv` | `slug`, `name`, `city`, `vk_url`, `demo`, `data_tag` |
| `participants.csv` | `slug`, `display_name`, `age_group`, `studio`, `city`, `consent_status`, `consent_at`, `demo`, `data_tag` |
| `blocks.csv` | `slug`, `day`, `title`, `starts_at`, `ends_at`, `stage`, `nominations`, `note`, `data_tag` |
| `performances.csv` | `slug`, `title`, `nomination`, `participants`, `scheduled_at`, `order_no`, `stage`, `status`, `video_url`, `source_id`, `demo`, `data_tag` |
| `nominations.csv` | `slug`, `name`, `style`, `format`, `age_group`, `levels`, `min_participants`, `max_participants`, `day`, `starts_at`, `ends_at`, `stage`, `status`, `note`, `source_id`, `demo`, `data_tag` |
| `judges.csv` | `slug`, `name`, `role`, `city`, `regalia`, `styles`, `blocks`, `source_id`, `photo`, `photo_author`, `photo_license`, `photo_use`, `photo_purpose`, `photo_source_url`, `photo_nature`, `demo`, `data_tag` |
| `media.csv` | `slug`, `title`, `kind`, `platform`, `url`, `preview_image`, `meta`, `nomination_slug`, `data_tag` |
| `commerce.csv` | `slug`, `title`, `category`, `price`, `status`, `description`, `cta_label`, `url`, `erid`, `data_tag` |
| `alerts.csv` | `id`, `status`, `title`, `text`, `link_slug`, `urgent` |
| `scores.csv` | `performance`, `nomination`, `studio`, `participant`, `score`, `place`, `published` |

Списки (`levels`, `nominations`, `participants`, `styles`, `blocks`) пишутся
через `|` (запятая тоже принимается). Время — `ЧЧ:ММ`, дата-время —
ISO 8601 с часовым поясом (`2026-12-12T10:00:00+05:00`). Шапка проверяется
целиком: лишняя или пропущенная колонка — ошибка, а не «мелочь».

Для несовершеннолетних `display_name` — инициалы (`Л. В.`), для 18+ допустимо
полное имя. Это проверяет модель `Participant`, а не только скрипт.

**Медиа и коммерция.** `media.csv` — ссылки на внешние хостинги: `kind` и
`platform` берутся из закрытых перечислений, `preview_image` — путь от
`static/` (`img/media/<слаг>.webp`), пустая клетка означает типографскую
заглушку. `commerce.csv` — товары, фотопакеты и партнёры: у `partner` цена
пустая, а `erid` заполняется только настоящим токеном ОРД.

У строк этих двух листов нет поля `demo`, поэтому `preview`-тег не проставляет
его: презентационность видна по баннеру предпросмотра и по тому, что строки
живут в overlay. Демонстрационные ссылки ведут на заглушки (`*.example`,
тестовые id хостингов) и не выдают себя за настоящие публикации: показать
вёрстку руководству можно, сослаться на несуществующий ролик — нельзя.

## 7.4. Тайминг номинаций

В «Положении» времени начала нет. Скрипт выводит границы номинации из её
выступлений внутри блока:

1. блок задаёт окно `starts_at`–`ends_at` и список номинаций;
2. выступления дают моменты `scheduled_at`;
3. начало номинации — первый момент (не раньше начала блока), конец — последний
   момент + 10 минут (не позже конца блока).

Если у номинации нет выступлений, момент вне блока или окно пустое — импорт
падает с сообщением, а не пишет «примерно». Патч содержит только `slug`,
`starts_at`, `ends_at`; всё остальное берётся из опубликованного YAML.

## 7.5. Порядок работы

```powershell
# 1. Проверить таблицы и overlay, ничего не записывая
.\.venv\Scripts\python.exe -m zaruba.sync_tables --check

# 2. Собрать overlay (перезаписывает только разделы из таблиц)
.\.venv\Scripts\python.exe -m zaruba.sync_tables

# 3. Посмотреть сайт в режиме предпросмотра
$env:ZARUBA_PREVIEW_ENABLED = "1"
.\.venv\Scripts\python.exe -m uvicorn zaruba.main:app --reload --port 8000
# /schedule и /faq покажут два демо-оффера, /results — заглушку свободного слота


# 4. Убрать все презентационные строки одной командой
.\.venv\Scripts\python.exe -m zaruba.sync_tables --drop-preview
```

`--check` сверяет не только таблицы, но и уже записанный overlay: устаревший или
лишний файл — ошибка, чтобы показанные страницы не разошлись с таблицами.
`--drop-preview` удаляет только overlay: CSV-таблицы остаются рабочим материалом для
следующего показа, а базовый YAML не меняется вовсе. Чтобы вернуть примеры,
достаточно снова выполнить `python -m zaruba.sync_tables`.

Без флага `ZARUBA_PREVIEW_ENABLED` сайт работает на подтверждённых фактах, а
`content/editions/2026.d/` не читается вовсе. С флагом:

- в шапке страницы появляется пометка «предпросмотр»;
- все страницы получают `noindex, nofollow` — даже если роутер передал другой
  `robots`;
- на расписании и главной вместо «тайминг не опубликован» выводится
  объяснение, что блоки демонстрационные.

Флаг не заменяет приёмку: перед публикацией `--drop-preview`, затем
`pytest`, `zaruba.content check`, `ruff`, `mypy` — по `AGENTS.md`.

## 7.6. Чего здесь нет

- **Файлов фото и видео в репозитории** — превью-карточки ссылаются на внешний
  хостинг и не копируют чужой кадр; изображение-постер — только своё и с правами
  (`docs/06` §6.5), иначе типографская заглушка.
- **`erid` из головы** — токен выдаёт ОРД; придуманный «пример» ломает
  `content check` по шаблону. Исключение одно: `content/offers.preview.yaml`,
  где токены `DEMO-PREVIEW-*` разрешены и файл читается только в preview;
  в боевой `content/offers.yaml` такой токен не пройдёт проверку.
- **XLSX как источник данных** — Google Таблицы читаются через CSV-экспорт,
  поэтому `openpyxl` (dev-зависимость) нужен только скрипту
  `scripts/export_master_xlsx.py`: он собирает книгу для организаторов
  `docs/templates/ZARUBA_2026_MASTER.xlsx` из тех же CSV. Обратного пути нет:
  книгу в git не правят, её пересобирают (`08-deploy-and-sheets.md` §8.1).
- **Записи `real` из таблицы** — намеренно, чтобы импорт не мог подменить
  опубликованный факт.

## 7.7. Синхронизация с Google Таблицами

Таблицы можно заполнять не в git, а в Google Таблицах — владельцу это ближе,
чем правка CSV в редакторе. Флаг `--from-sheets` забирает листы по публичным
ссылкам экспорта (`…/export?format=csv&gid=…`), проверяет их теми же правилами,
что и локальные файлы, и только потом перезаписывает `docs/templates/*.csv` и
overlay.

| Правило | Почему так |
|---|---|
| адреса листов — из `ZARUBA_SHEET_ID` и JSON-карты `ZARUBA_SHEETS_MAP` | один секрет вместо восьми URL, и карта проверяется на полноту |
| без переменных — работа на локальных CSV | локальный запуск и тесты не зависят от сети |
| таймаут 10 с, HTML вместо CSV — отдельная ошибка | закрытая таблица отвечает страницей входа, и молча принять её за данные нельзя |
| все листы или ничего | половина новых и половина старых строк — это испорченный каталог, а не «почти готово» |

Пошаговая настройка (доступ, `SHEET_ID`, `gid`, секреты GitHub, режим показа) —
`08-deploy-and-sheets.md`.

## 7.8. Демонстрационные рекламные офферы

Нативные вставки (§6.27) на показе должны быть заполнены, но выдуманный
рекламодатель и `erid` не могут жить в боевом `content/offers.yaml`.
Поэтому примеры лежат отдельным файлом:

| Слот | Заголовок | CTA | `erid` | Срок |
|---|---|---|---|---|
| `schedule_top` | Трансфер и парковка у КТЗ «Золотые ворота Сибири» | Построить маршрут | `DEMO-PREVIEW-01` | 2026-12-20 |
| `checklist_card` | Горячие обеды и кофе в 3 минутах от зала | Посмотреть меню | `DEMO-PREVIEW-02` | 2026-12-20 |

Правила:

- файл `content/offers.preview.yaml` читается только при
  `ZARUBA_PREVIEW_ENABLED=1`: без флага `resolve_tip()` его не открывает;
- демо-оффер — запасной вариант: если для слота есть действующий боевой
  оффер, показывается он, а пример не дублирует интеграцию;
- `protocols_inline` демо-оффера не имеет: на показе видно и заполненный слот,
  и пустое место под интеграцию;
- `valid_until` проверяется как у боевых: после 2026-12-20 пример исчезает,
  и слот снова становится заглушкой;
- `erid` с префиксом `DEMO` — не маркировка ОРД, а пометка «пример»;
  домены `.example` зарезервированы RFC 2606 и не существуют в сети;
- `python -m zaruba.content check` валидирует файл всегда, даже без preview:
  сломанный пример ломает проверку до показа;
- `ZARUBA_SERVICE_TIPS_ENABLED=false` в preview не выключает слоты: показ —
  отдельный режим, страницы и так `noindex`;
- в prod `ZARUBA_PREVIEW_ENABLED=false`, поэтому примеры не попадают
  на публичный сайт.
