# 09. Mini App в MAX и бесплатный GitHub Pages

> Ответвление `feat/max-miniapp`: тот же сайт открывается внутри мессенджера
> MAX как мини-приложение. Инфраструктура — статика на GitHub Pages, 0 ₽.
> Спецификация MAX: <https://dev.max.ru/docs/webapps/introduction/> и
> <https://dev.max.ru/docs/webapps/bridge>.

## 9.1. Что меняет флаг `ZARUBA_MAX_MINIAPP=true`

| Что | Без флага | С флагом |
|---|---|---|
| MAX Bridge | не подключается | `https://st.max.ru/js/max-web-app.js` в конце `body`, затем `static/max-bridge.js` |
| CSP | `script-src 'self'`, `frame-ancestors 'none'` | `script-src 'self' https://st.max.ru`, `frame-ancestors 'self' https://max.ru https://*.max.ru` |
| `X-Frame-Options` | `DENY` | не отправляется: иначе десктопный клиент MAX не встроит страницу |
| Шапка | логотип «ЗАРУБА · Тюмень» и меню | логотип скрыт (нативный заголовок MAX уже называет бота), в меню добавлена «Главная» |
| Кнопка «Назад» | нет | `BackButton.hide()` на главной, `show()` на внутренних страницах, нажатие — `history.back()` |
| Внешние ссылки | обычный переход | `target="_blank"` перехватывается и открывается через `WebApp.openLink()` |
| Приветствие | нет | окно `#max-welcome-modal` из `partials/max-welcome.html` на первом визите, стили `static/max-miniapp.css`; повторно — кнопка «Гид по приложению» в футере |

Вне MAX (`window.WebApp.platform === null`) адаптер не делает ничего: обычный
сайт остаётся обычным сайтом.

## 9.2. Локальная проверка

```powershell
$env:ZARUBA_MAX_MINIAPP = "true"
python -m uvicorn zaruba.main:app --port 8000
# в ответе: script-src ... https://st.max.ru, X-Frame-Options отсутствует,
# в шапке нет логотипа
```

Сборка ровно того, что уедет на Pages:

```powershell
$env:ZARUBA_ENV = "prod"
$env:ZARUBA_MAX_MINIAPP = "true"
python scripts/build_max_dist.py
python -m http.server 8001 --directory dist   # проверка относительных ссылок
```

Отдельно проверяется подпись `?startapp=`: открыть
`http://127.0.0.1:8001/?startapp=schedule` — адаптер перейдёт на
`schedule.html`, только если файл существует. Окно приветствия (§9.11) при
открытии по диплинку не показывается: ссылка сразу ведёт на раздел. Вернуть
окно вручную — очистить `localStorage` или нажать «Гид по приложению» в футере.

## 9.3. Включить GitHub Pages (5 шагов)

1. Ветка `feat/max-miniapp` запушена в GitHub; файл `.github/workflows/pages-max.yml` в ней есть.
2. Репозиторий → **Settings** → **Pages** → **Source**: выбрать **GitHub Actions**
   (не «Deploy from a branch»: тогда Pages возьмёт корень репозитория, а не `dist/`).
3. Репозиторий → **Actions** → workflow **pages-max** → **Run workflow**, ветка
   `feat/max-miniapp`. Пуш в эту ветку запускает его сам.
4. Дождаться зелёного job `deploy`; адрес будет в выводе job и в
   **Settings → Pages**: `https://<владелец>.github.io/<репозиторий>/`.
5. Открыть адрес в браузере: страницы и CSS должны работать без сервера.

Секреты `ZARUBA_SHEET_ID` и `ZARUBA_SHEETS_MAP` — те же, что у `sync-sheets.yml`
(`08-deploy-and-sheets.md`). Если `ZARUBA_SHEETS_MAP` не задан, сборка идёт на
данных репозитория и пишет `::notice::`, а не падает.

## 9.4. Ссылка на мини-приложение в MAX

1. Открыть <https://business.max.ru/self> → **Чат-боты** → **Перейти**.
2. Выбрать бота → **⋮** → **Настройки**.
3. Вставить адрес из шага 9.3 в поле URL мини-приложения.
4. Выбрать вид кнопки (**Открыть**, **Старт**, **Играть** или без названия) →
   **Сохранить**.

Требования MAX к адресу: только `https://`, не длиннее 1024 символов, латиница,
цифры, точка и дефис, без пробелов. Адрес `github.io` подходит; свой домен не
нужен. Если репозиторий переименован, адрес в настройках бота надо обновить —
иначе кнопка ведёт на 404.

## 9.5. Диплинки `?startapp=`

Формат: `https://max.ru/<bot>?startapp=<значение>`, значение — до 512 символов.
MAX передаёт его мини-приложению в `window.WebApp.initDataUnsafe.start_param`.
Адаптер понимает значение как путь страницы: `[a-z0-9]`, затем до 63 символов
`[a-z0-9/-]` — то есть и `schedule`, и вложенный `participants/ivan-petrov`;
переход только на существующий `<путь>.html` статической сборки.

| Диплинк | Куда попадёт пользователь |
|---|---|
| `https://max.ru/<bot>?startapp=schedule` | `schedule.html` — расписание |
| `https://max.ru/<bot>?startapp=participants` | `participants.html` — каталог участников |
| `https://max.ru/<bot>?startapp=participants/ivan-petrov` | карточка участника |
| `https://max.ru/<bot>?startapp=studios/pechat-tantsa` | карточка студии |
| `https://max.ru/<bot>?startapp=results` | `results.html` — результаты |
| `https://max.ru/<bot>` | главная, `start_param` пуст |

Доступные slug — это имена страниц из `scripts/build_static_preview.py`
(`SEED_PAGES`): `event`, `schedule`, `performances`, `participants`, `studios`,
`judges`, `results`, `tickets`, `venue`, `faq`, `media`, `privacy`, `about`,
`rules`, `takedown`, `glossary`, `history`, `ratings`, `search`.

Не передавайте в `startapp` конфиденциальные данные открытым текстом — только
одноразовые токены или идентификаторы сессии (требование MAX). Редирект
работает в статической сборке; на локальном FastAPI-стенде `<slug>.html` нет,
поэтому диплинк просто открывает главную.

## 9.6. Обновление и после слияния в `main`

- По расписанию (`*/30 * * * *`) и по пушу (`main`, `feat/max-miniapp`) workflow
  забирает таблицы, гоняет `zaruba.content check`, `pytest`, собирает `dist/` и
  публикует Pages.
- GitHub запускает `schedule` только из workflow-файла в **ветке по умолчанию**,
  поэтому `main` есть и в `on.push.branches`, и в расписании. До слияния
  расписание молчит: работают пуш в `feat/max-miniapp` и **Run workflow**.
- `deploy.yml` и `sync-sheets.yml` запускаются только вручную: постоянная
  публикация — Pages, а выкладка на VPS и коммит таблиц в git нужны лишь при
  переезде (`08-deploy-and-sheets.md` §8.4).
- Коммитов workflow почти не делает: данные таблиц живут в опубликованном
  `dist/`, а не в истории. Исключение одно — лог срочных оповещений
  `content/editions/<год>.d/sent_alerts.json` (§9.9): без него следующий запуск
  разослал бы те же строки повторно.

## 9.7. Ограничения, о которых нужно помнить

- GitHub Pages отдаёт файлы как есть и **не присылает заголовки** из
  `middleware.py`: CSP и `X-Frame-Options` действуют только на FastAPI-стенде.
  Для Mini App это не проблема (страница и так внутри MAX), но проверять
  политику надо на `uvicorn`, а не на Pages.
- Копия на `github.io` закрыта от индексации файлом `robots.txt` с
  `Disallow: /`: `canonical` в статике срезается, а JSON-LD сохраняет адреса
  `testserver` — пусть робот лучше не видит эту копию вовсе.
- Поиск и фильтры — динамика FastAPI: в статике форма открывает каталог без
  параметров.
- Карточки участников, студий и выступлений в публичной сборке появляются
  только вместе с подтверждёнными данными: демо-строки из overlay
  `content/editions/2026.d/` включаются флагом `ZARUBA_PREVIEW_ENABLED=1` и на
  Pages намеренно выключены, поэтому каталоги показывают честные пустые
  состояния.
- `dist/` в `.gitignore`: публикуется артефакт сборки, а не папка в git.

## 9.8. Бот-проводник: «напиши слово — получи ссылку»

Бот живёт в том же приложении, что и сайт: MAX присылает событие на
`POST /max/webhook`, FastAPI отвечает `200` и уже после ответа отправляет
сообщение в чат через `platform-api2.max.ru/messages`. Отдельный контейнер,
база и очередь не нужны: ответ зависит только от текста события и настроек
(`src/zaruba/services/max_bot.py`).

| Событие | Ответ бота |
|---|---|
| `bot_started`, `/start`, `/start@<бот>`, «привет», «меню» | приветствие с подсказкой «открыть сайт можно по клику на кнопку рядом с полем для сообщений», кнопки «Открыть в MAX» и «Открыть сайт» |
| слово-раздел («расписание», «билеты», «как добраться») | название раздела и ссылка на его страницу |
| «билеты», «цена», «вход» | цена каждого билета по дням и действующий взнос участника |
| «расписание», «тайминг», «во сколько» | блоки по дням с временем; нет тайминга — так и написано |
| «где», «адрес», «площадка» | даты, адрес КТЗ «Золотые ворота Сибири», кнопка `/venue` |
| название студии или имя участника (от 4 символов) | сводка выступлений и кнопка на карточку |
| непонятный текст, пустое сообщение | список доступных разделов |
| сообщение от бота (`is_bot`), правки, удаления, `bot_stopped` | ответа нет |

### Ответы из живого контента

`plan_reply(update, settings, edition=…, venue=…, today=…)` получает тот же
`Edition`, что и страницы сайта (`load_latest`, кэш по отпечатку файлов), поэтому
бот не дублирует цифры, а берёт их из `content/editions/<год>.yaml`:

- **цена** — `tickets[].price` по дням; взнос участника считается по `early_until`
  и переданной дате `today`: до срока — ранняя ставка и её дедлайн, после —
  поздняя и дата, когда ранняя закончилась (`services/edition.fee_prices`);
- **блоки** — `blocks_for_day`, время `ЧЧ:ММ–ЧЧ:ММ` и название блока; у 2026
  тайминга в «Положении» нет, поэтому бот пишет «ещё не опубликован», а не
  выдумывает часы;
- **площадка** — даты и `Venue.address_line` из `content/venues.yaml`;
- **студия или участник** — поиск по имени без учёта кавычек и `ё` (совпадение
  ищется в обе стороны, короче 4 символов не ищем): ответ перечисляет до пяти
  выступлений с временем, номинацией и названием номера, а `open_app` ведёт на
  карточку `studios/<slug>` или `participants/<slug>` (§9.5).

Контент битый (`ContentError`) — webhook всё равно отвечает `200`, а бот
отвечает общей фразой со ссылкой: молчание хуже неточной формулировки, а 500
заставил бы MAX отписаться от бота.

Основа слова, а не целое: «расписание», «расписанию» и «расписании» ведут на
одну страницу. Проверяются по убыванию длины, поэтому «о сайте» — это раздел
«О сайте», а не «сайт» вообще.

| Слово | Раздел | Слово | Раздел |
|---|---|---|---|
| событ, номинац, возраст | `/event` | вопрос, faq | `/faq` |
| расписан, тайминг, блоки | `/schedule` | фото, видео, медиа | `/media` |
| выступлен | `/performances` | персональн, приват | `/privacy` |
| участник | `/participants` | о сайте, проект | `/about` |
| студи, школ | `/studios` | правил, положени | `/rules` |
| жюри, судь | `/judges` | удал, жалоб | `/takedown` |
| результат, победител | `/results` | глоссар, термин, направлен | `/glossary` |
| билет, вход, зрител | `/tickets` | истори, архив | `/history` |
| площадк, как добрат | `/venue` | рейтинг, балл | `/ratings` |

Кнопка `open_app` передаёт `slug` раздела мини-приложению — тот же параметр,
что понимает `?startapp=` (§9.5), поэтому человек попадает сразу на нужную
страницу. Кнопка `link` ведёт на саму страницу сайта. Нет `ZARUBA_MAX_BOT_NAME`
— остаётся только ссылка; нет адреса сайта — только текст.

| Переменная | Что это |
|---|---|
| `ZARUBA_MAX_BOT_TOKEN` | токен бота: «Чат-боты» → **⋮** → **Настройки** |
| `ZARUBA_MAX_BOT_SECRET` | секрет подписки, 5–256 символов `A–Z a–z 0–9 _ -` |
| `ZARUBA_MAX_BOT_NAME` | публичное имя бота для кнопки `open_app` |
| `ZARUBA_MAX_BOT_SITE_URL` | адрес сайта для ссылки; пусто — `ZARUBA_PUBLIC_BASE_URL` |
| `ZARUBA_MAX_BOT_CA_FILE` | PEM с корневым сертификатом Минцифры (см. ниже) |

Токен и секрет — это и есть включатель: без любого из них адрес `/max/webhook`
отвечает `404`, чтобы ненастроенный бот не висел открытым в интернете.

Порядок включения:

1. Задать переменные в `.env` на сервере и перезапустить `web`.
2. Подписать адрес на события (ключ — токен, URL — HTTPS на 443, без порта):

   ```bash
   curl -X POST "https://platform-api2.max.ru/subscriptions" \
     -H "Authorization: $ZARUBA_MAX_BOT_TOKEN" \
     -H "Content-Type: application/json" \
     -d '{"url":"https://<домен>/max/webhook","update_types":["message_created","bot_started"],"secret":"<секрет>"}'
   ```

3. Проверить, что адрес закрыт без секрета: `curl -s -o /dev/null -w '%{http_code}'
   -X POST https://<домен>/max/webhook` → `403`. Написать боту в MAX — ответ
   должен прийти в течение пары секунд.

Что важно помнить:

- **Ответ webhook — всегда `200`.** Любой другой код MAX считает сбоем доставки,
  повторяет запрос 10 раз и через 8 часов молчания отписывается сам. Поэтому
  мусор в теле — тоже `200`, а сбой отправки виден только в журнале `zaruba.max_bot`.
- **Секрет обязателен.** `X-Max-Bot-Api-Secret` — единственное доказательство,
  что запрос пришёл от MAX; сравнение идёт `secrets.compare_digest`.
- **Сертификат Минцифры.** Исходящие запросы к `platform-api2.max.ru` проверяют
  TLS как обычно: если в контейнере нет российского корневого сертификата,
  отправка падает с `SSL: CERTIFICATE_VERIFY_FAILED`. Лечится тем, что PEM
  кладётся в файл, а путь — в `ZARUBA_MAX_BOT_CA_FILE`; отключать проверку
  сертификата нельзя.
- **Состояния нет**, поэтому повторная доставка одного события даст второй
  ответ: дедупликация потребовала бы хранилища `mid`, а вред от дубля меньше
  цены базы в проводнике. Лимит MAX — 2 сообщения в секунду на диалог — при
  одном ответе на событие соблюдается.
- Бот отвечает ссылкой, но не отвечает вместо сайта: тексты, цифры и ответы
  организаторов остаются на страницах, где у каждого факта есть источник.

## 9.9. Срочные оповещения: лист `alerts` и рассылка в MAX

Оповещение — короткая строка «что изменилось» (перенос блока, отмена номинации,
вход с другого крыльца). Живёт она в отдельном листе `alerts` той же Google
Таблицы, а не в выпуске: плашка нужна на сутки, выпуск — на год.

Лист `alerts` (шапка ровно такая, порядок колонок значения не имеет):

| Колонка | Что это | Ограничения |
|---|---|---|
| `id` | ключ строки и ключ лога отправки | slug: латиница, цифры, дефис |
| `status` | `draft` — черновик, `send` — опубликовано | только эти два значения |
| `title` | заголовок плашки | 3–80 символов |
| `text` | само оповещение | 10–280 символов |
| `link_slug` | страница сайта для кнопки и ссылки | пусто или slug страницы |
| `urgent` | `true` — показать плашку на сайте | `true` / `false` |

Пустая таблица — законное состояние: «оповещений нет», а не ошибка. Строки
`send` без `urgent` уходят в MAX, но вёрстку не перекрашивают; `draft` не
уходит никуда. Файл `content/alerts.yaml` собирает синхронизация:

```powershell
python -m zaruba.sync_tables --from-sheets      # заодно пишет content/alerts.yaml
python -m zaruba.sync_tables --check --alerts-out content/alerts.yaml
```

`--check` сравнивает лист с файлом построчно и называет `id` и поле, которые
разошлись.

**Плашка на сайте.** Опубликованное срочное оповещение (`status=send`,
`urgent=true`) выводится яркой полосой в верхней части главной и расписания —
над шапкой, до контента. Вёрстка ничего не фильтрует: выбор строки делает
`services/alerts.active_alert` (первая подходящая строка в порядке таблицы,
поэтому новая строка ставится выше старой).

**Рассылка в MAX.**

```powershell
python -m zaruba.max_notify --send-alerts            # отправить очередь
python -m zaruba.max_notify --send-alerts --dry-run  # показать очередь, не отправляя
```

Команда берёт строки `status=send`, которых нет в
`content/editions/<год>.d/sent_alerts.json`, отправляет сообщение
`post_message()` в чат или канал `ZARUBA_MAX_ALERT_CHAT_ID` с кнопкой
`open_app` на `link_slug` и записывает `id` в лог **сразу после каждого
успешного сообщения**. Не доставлено — `id` в лог не попадает и строка
повторится при следующем запуске; код возврата при этом `1`.

| Переменная | Что это |
|---|---|
| `ZARUBA_MAX_ALERT_CHAT_ID` | числовой `chat_id` канала или чата для рассылки |
| `ZARUBA_MAX_BOT_TOKEN` | токен бота; не задан — команда пишет «рассылка пропущена» и выходит с `0` |

В `pages-max.yml` рассылка идёт после сборки статики, а лог коммитится тем же
job'ом (`contents: write`) с сообщением `[skip ci]`. Пуш из workflow через
`GITHUB_TOKEN` новых запусков не вызывает, поэтому цикла нет. Сбой доставки
помечен `continue-on-error`: страницы публикуются в любом случае.

**Как разослать прямо сейчас:** правка таблицы → **Actions → pages-max → Run
workflow**. Обычный путь — расписание `*/30`: тот же прогон и обновляет
страницы, и рассылает новые строки.

**Почему лог, а не `sent_at` в таблице:** запись обратно в чужую Google Таблицу
требует права записи у CI. Лог в репозитории дешевле и виден в истории git.
Ограничение честное: два прогона одновременно (ручной и плановый) могут успеть
отправить одну строку дважды — параллельные запуски `pages-max` разводит
`concurrency: pages-max`.

## 9.10. Бот без VPS: long polling

Вебхук требует домена с HTTPS и белого IP. Mini App живёт на бесплатном GitHub
Pages, поэтому основной режим бота — **long polling**: бот сам спрашивает MAX
`GET /updates`, сервер держит запрос до 30 секунд и отвечает сразу, как только
событие появилось. Ни адреса, ни сертификата на входе не нужно.

```powershell
python -m zaruba.max_bot --once        # один запрос: проверка токена и TLS
python -m zaruba.max_bot --polling     # цикл до Ctrl+C
python -m zaruba.max_bot --polling --timeout 30 --pause 1
```

- Работает с любого ПК в день чемпионата: достаточно `ZARUBA_MAX_BOT_TOKEN` и
  (при необходимости) `ZARUBA_MAX_BOT_CA_FILE`. Запуск без токена — код `1` и
  объяснение; путь к несуществующему сертификату проверяется до сети.
- Ответы те же, что у вебхука: `poll_once` собирает пачку событий, читает
  `Edition` один раз и отправляет ответы через тот же `post_message`.
- Сеть отвалилась — пустой ответ и следующий запрос с тем же `marker`: цикл
  переживает ночной обрыв. `marker` живёт в памяти процесса: без него MAX
  отдаёт только последнее событие, поэтому после перезапуска возможен один
  повторный ответ. Хранилище ради этого не заводим.
- Вебхук `/max/webhook` остаётся рабочим: переезд на VPS — это `POST
  /subscriptions` и переменные окружения, а не правка кода (§9.8).
- Long polling и вебхук одновременно держать не нужно: MAX доставит событие
  тому каналу, который подписан. При живом вебхуке опрос просто не нужен.

Ограничение: бесплатный воркер CI для этого не годится — job GitHub Actions
живёт минуты, а бот нужен часами. Подойдёт любой ПК с Python и интернетом.

## 9.11. Приветственное окно (онбординг)

Первое открытие мини-приложения начинается с короткой инструкции: что смотреть,
где искать своих и как спросить бота. Окно — часть шаблона, а не отдельная
страница: своего адреса у него нет, и в `dist/` оно уезжает с каждой страницей.

| Что | Файл | Правило |
|---|---|---|
| Разметка | `templates/partials/max-welcome.html` | `#max-welcome-modal`, `role="dialog"`, `aria-modal="true"`, `hidden` по умолчанию |
| Стили | `static/max-miniapp.css` | только при `ZARUBA_MAX_MINIAPP=true`; `style.css` держится в бюджете 32 000 байт |
| Логика | `static/max-bridge.js` | флаг `zaruba_max_welcome_v1`, `data-welcome-close`, `data-welcome-open` |

Правила поведения:

- окно показывается на первом визите, если в `localStorage` нет флага
  `zaruba_max_welcome_v1` и не передан `start_param`: диплинк на раздел сразу
  ведёт к цели;
- любое нажатие на элемент с `data-welcome-close` (включая кнопки-ссылки
  «Смотреть расписание», «Студии и участники», «Билеты и площадка») ставит флаг
  и скрывает окно (`hidden = true`) — переход при этом остаётся обычным;
- кнопка «Гид по приложению» в футере (`data-welcome-open`) открывает окно
  повторно; флаг она не сбрасывает, поэтому после перезагрузки окно снова
  спрятано;
- `try/catch` вокруг `localStorage` — для приватного режима WebView: исключение
  не ломает страницу, окно просто покажется ещё раз.

Ссылки внутри окна — обычные `<a href="/schedule">`: `build_max_dist.py`
переписывает их в `schedule.html` (и `../schedule.html` на вложенных карточках),
поэтому на GitHub Pages они работают без сервера. `max-miniapp.css` входит в
`ASSET_VERSION`, а сборка проверяет, что файл попал в `dist/static/`.

Проверки: `tests/test_max_miniapp.py` (разметка, `hidden`, стили, флаг и
`start_param`) и `tests/test_build_max_dist.py` (относительные ссылки внутри
окна и копия стилей в `dist/`).


## 9.12. Запуск бота 24/7 на своем мини-ПК

Домашний ПК заменяет VPS: long polling не требует ни домена, ни белого IP
(§9.10), поэтому бот может жить на машине, которая и так включена круглосуточно.
Нужны `.venv`, токен в `.env` и одна задача в Планировщике Windows.

### Что проверено на этой машине (18.11.2026)

| Что | Значение | Вывод |
|---|---|---|
| Система | Windows 11 Pro 22621, Ryzen 5 7500F (6/12), 32 ГБ ОЗУ, 604 ГБ свободно | память и диск не в дефиците |
| Сон от сети | `powercfg`: `STANDBYIDLE` AC = `0x0` (никогда), гибернация выключена | ПК не заснёт вместе с ботом |
| TLS до `platform-api2.max.ru` | `ssl.create_default_context()` и системные корни: ответ `429` (лимит запросов), не `CERTIFICATE_VERIFY_FAILED` | `ZARUBA_MAX_BOT_CA_FILE` не нужен |
| Память бота | 58 МБ RSS у интерпретатора, 6 потоков | 0,2 % от 32 ГБ |
| Процессор | 200 циклов опроса — 0,09 с CPU; в простое long polling держит сокет | меньше 1 % |
| Обновление данных | `sync_tables --check` 0,37 с, `content check` 0,38 с вместе со стартом процесса | раз в 30 минут незаметно |

Сертификат Минцифры нужен контейнеру на Linux, где нет российских корней
(§9.8). На Windows корни берутся из системного хранилища, поэтому
`ZARUBA_MAX_BOT_CA_FILE` остаётся закомментированной строкой в `.env`.

| Файл | Что делает |
|---|---|
| `deploy/local-pc/run_bot_loop.ps1` | супервизор: запуск бота, пауза 5 с после падения, обновление данных раз в 30 минут, ротация лога |
| `deploy/local-pc/install_autostart.ps1` | задача `ZarubaMaxBot` в Планировщике: регистрация, запуск, `-Remove` |
| `logs/max_bot.log` | вывод бота; после 5 МБ проворачивается в `.1`, `.2`, `.3` |
| `logs/max_bot_loop.log` | что делал супервизор: перезапуски, `git pull`, выгрузка таблиц |

### Включение: три шага

1. **Токен.** `Copy-Item .env.example .env`, затем в `.env`:

   ```dotenv
   ZARUBA_MAX_BOT_TOKEN=<токен из «Чат-боты» → ⋮ → «Настройки»>
   ```

   Проверка до автозапуска: `python -m zaruba.max_bot --once` — в ответе
   `OK опрос выполнен, marker: …`. Если нужна и выгрузка таблиц, допишите
   `ZARUBA_SHEET_ID` и `ZARUBA_SHEETS_MAP` (`08-deploy-and-sheets.md` §8.1): их
   читает супервизор, а не `pydantic-settings`.

2. **Автозагрузка — одна команда:**

   ```powershell
   powershell -ExecutionPolicy Bypass -File deploy\local-pc\install_autostart.ps1
   ```

   Скрипт проверяет `.venv`, токен и настройку сна, регистрирует задачу на вход
   в систему, запускает её и печатает состояние. Флаги: `-AsSystem` (старт при
   включении ПК, до входа в систему; нужен администратор), `-PreventSleep`
   (выключить сон от сети, тоже от администратора), `-NoStart` (только
   зарегистрировать), `-Remove` (остановить и снять задачу).

3. **Проверка, что бот работает в фоне:**

   ```powershell
   Get-ScheduledTask -TaskName ZarubaMaxBot | Select-Object TaskName,State
   Get-Content logs\max_bot_loop.log -Tail 5 -Encoding UTF8
   Get-Content logs\max_bot.log -Tail 5 -Encoding UTF8
   ```

   `State = Running`, а `LastTaskResult = 267009` (`0x41301`) — это
   «выполняется», а не ошибка. В журнале бота строки появляются только на
   события: `ответов отправлено: 1, marker …` — сообщение принято и ответ
   отправлен; `опрос событий не удался` — сеть отвалилась, и это нормально, пока
   следующая строка не станет успешной.

### Почему цикл устроен именно так

- **Перезапуск через 5 секунд.** Проверено на живой задаче: падение в `15:13:21`,
  новый запуск в `15:13:26`. Обрыв домашнего интернета не требует человека.
- **Данные обновляются без перезапуска.** `poll_once` читает контент на каждом
  цикле опроса (`load_latest`), поэтому `git pull --ff-only` и
  `sync_tables --from-sheets` подхватываются на лету. `pull` идёт только на
  чистом дереве (`--untracked-files=no`): правка в отслеживаемом файле важнее
  свежести. Выгрузка таблиц — только если задан `ZARUBA_SHEETS_MAP`; overlay
  `content/editions/2026.d` виден при `ZARUBA_PREVIEW_ENABLED=1`, публичные факты
  приезжают в `content/editions/2026.yaml` из `main`.
- **Два процесса `python.exe` — норма.** В этом окружении
  `.venv\Scripts\python.exe` — лаунчер `py.exe`, он запускает интерпретатор
  дочерним процессом. Поэтому остановка идёт `taskkill /T` по дереву: иначе
  «остановленный» бот продолжал бы отвечать в MAX.
- **Токен читает супервизор.** У задачи Планировщика нет ни консоли, ни профиля
  пользователя, поэтому `.env` разбирается в `run_bot_loop.ps1` и передаётся
  дочерним процессам через окружение. Без токена цикл завершается с кодом `3`, а
  не перезапускается каждые 5 секунд: одна и та же ошибка в логе не помогает.
- **Ротация останавливает бота.** Открытый на Windows файл не переименовать,
  поэтому лог проворачивается коротким перезапуском. Цена — тот же один повторный
  ответ, что и после любого перезапуска (`marker` живёт в памяти, §9.10), и это
  реже, чем раз в две недели при 5 МБ.

### Ограничения

- `Stop-ScheduledTask` гасит только `powershell`, дочерний бот переживает
  остановку. `run_bot_loop.ps1 -Stop` (его и вызывает `-Remove`) снимает процесс
  по `logs/max_bot.pid`, а при следующем старте супервизор добивает остаток сам.
- Смена домашнего IP боту не мешает: он сам обращается к MAX. Проблема только у
  спящего ПК, поэтому таймаут проверяется при установке и печатается в отчёте.
- `-AsSystem` работает без входа в систему, но у SYSTEM нет учётных данных git:
  публичный репозиторий тянется анонимно (`safe.directory` передаётся явно), а
  приватный `git pull` оставит в журнале ошибку и продолжит опрос.




## 9.13. Мониторинг постов ВКонтакте

Официальные анонсы выходят в сообществе «ЗАРУБА72» (`vk.com/zaruba72champ`), и
фан-сайт не должен узнавать о них последним. Модуль `zaruba.vk_watch` опрашивает
`wall.get` и присылает новый пост в MAX.

**Почему API, а не страница.** Проверено 18.11.2026: `vk.com/zaruba72champ`
отдаётся капчей (в 280 КБ ответа — ни одной ссылки на запись), `m.vk.com` — тоже
без постов, `vk.com/rss.php` отвечает 404, а API без токена — ошибкой
`15: Access denied: token required`. Значит источник один:

```
https://api.vk.com/method/wall.get?domain=zaruba72champ&count=10&filter=owner&v=5.199
```

`filter=owner` отбрасывает репосты чужой стены: новостью считается запись самого
сообщества. Числовой `owner_id` в настройках не нужен — он приходит в каждом
посте и из него собирается адрес `wall<owner_id>_<id>`.

**Токен.** `ZARUBA_VK_TOKEN` — единственный включатель: без него команда пишет
«проверка пропущена» и выходит с кодом 0 (как рассылка оповещений без бота).

| Способ получить | Кому доступен | Срок жизни |
|---|---|---|
| Standalone-приложение + Implicit Flow, `scope=wall,offline` | подтверждённому аккаунту VK | долгий (`offline`) |
| Сервисный ключ сообщества («Управление» → «Работа с API») | администратору паблика | бессрочный |

Токен живёт только в `.env` (и в секретах CI, если понадобится второй контур).
В запросе он уходит заголовком `Authorization: Bearer`: в query string он попал
бы в текст ошибки `urllib`, а оттуда — в журнал.

**Команды.**

```powershell
python -m zaruba.vk_watch --init        # запомнить хвост, ничего не отправляя
python -m zaruba.vk_watch --once        # один цикл проверки
python -m zaruba.vk_watch --once --dry-run
python -m zaruba.vk_watch --loop        # опрос до Ctrl+C (--interval 60)
```

`--init` нужен один раз после установки: без него первый цикл разослал бы все
последние посты разом.

**Что уходит в MAX.** Текст поста (до 900 символов, обрезка по границе слова),
подпись «ВКонтакте, сообщество ЗАРУБА72» со ссылкой на пост и кнопка «Открыть
пост». У поста без текста (видео) так и написано: «Пост без текста (вложение:
video)» — придумывать подпись вместо автора нельзя. Картинки не копируются: на
чужой кадр нужно отдельное основание (`docs/06` §6.5).

| Переменная | Что это |
|---|---|
| `ZARUBA_VK_TOKEN` | токен VK; не задан — проверка пропускается, код возврата 0 |
| `ZARUBA_VK_CHAT_ID` | chat_id получателя; пусто — `ZARUBA_MAX_ALERT_CHAT_ID` |
| `ZARUBA_VK_INTERVAL` | период опроса, с (по умолчанию 60) |
| `ZARUBA_VK_POSTS` | сколько последних постов читать за цикл (по умолчанию 10) |

**Повторной отправки нет.** Ключи отправленных постов (`owner_id_id`) лежат в
`logs/vk_seen.json` (`logs/` в `.gitignore`) и пишутся сразу после каждого
сообщения: сбой на третьем посте не отправит первые два заново. Ключ, а не
«последняя дата», потому что закреплённый пост висит в начале ленты месяцами со
старой датой. Обрыв сети — пустая лента и строка в журнале, лог не меняется.

**Круглосуточно.** `run_bot_loop.ps1` поднимает мониторинг вторым процессом
рядом с ботом, если `ZARUBA_VK_TOKEN` задан: тот же перезапуск через 5 секунд,
ротация `logs/vk_watch.log` и `git pull` раз в 30 минут. Отдельной задачи
Планировщика не нужно — автозапуск остаётся один (`install_autostart.ps1`).

**Чего модуль не делает.** Не пишет в `content/` сам: пост либо уходит цитатой,
либо становится черновиком, который публикует только владелец кнопкой в MAX
(§9.14). Цифры из поста не переносятся: факт без источника не публикуется
(AGENTS.md), а суммы, номинации и тайминг берутся из «Положения» и таблицы
организаторов. Уведомление — повод открыть таблицу, а не замена ей.


## 9.14. Полуавтоматическая публикация постов из VK через бота

Конвейер целиком, без Google Cloud API и без ручной правки YAML:

```
новый пост vk.com/zaruba72champ
  → vk_watch разбирает его в черновик (logs/vk_drafts.json)
  → карточка в чат владельца с кнопками «Опубликовать» / «Отклонить»
  → нажатие владельца: content/<файл>.yaml + content check + commit + push в main
  → GitHub Pages пересобирает мини-приложение (30–40 с)
```

Последний шаг — обычный `push` в `main`: `pages-max.yml` собирает статику на
каждый пуш, поэтому отдельный деплой не нужен (§9.6).

### Разбор поста: `services/vk_parser.py`

| Что решает | Правило |
|---|---|
| тип черновика | `media`, если в тексте ссылка на `vk.com`, `vkvideo.ru`, `rutube.ru`, `disk.yandex.ru`, `cloud.mail.ru`, `youtube.com` или в посте вложение `video`/`short_video`; иначе `alert`, если есть слово-сигнал («перенос», «задержка», «внимание», «отмена», «старт», «закрытие/открытие», «регистрация», «измени») |
| `id` | `vk-<id поста>`; тот же `id` — `slug` карточки медиа, поэтому повторная публикация невозможна |
| `title` | первая осмысленная строка: без ссылок, хештегов и строк короче трёх символов; обрезка по границе слова до 80 символов |
| `text` | текст поста без ссылок и хештегов, до 280 символов, с обязательным хвостом `Источник: https://vk.com/wall…` — факт без первоисточника не публикуется (AGENTS.md) |
| `link_slug` | раздел сайта по ключевым словам: билеты/касса/взнос/регистрация → `tickets`, площадка/адрес → `venue`, расписание/блок/перенос → `schedule`, итоги/протокол → `results`, фото/видео/эфир → `media`; ничего не совпало — `None`, и плашка будет без ссылки |
| `has_picture` | вложения `photo`, `graffiti`, `doc`, `market_album` или ссылка `vk.com/photo` → в карточку владельцу уходит «В посте есть картинка — проверь детали глазами перед публикацией» |
| нераспознанный пост | черновика нет: уходит прежнее уведомление с цитатой и ссылкой (§9.13), потому что раздел и текст плашки пришлось бы выдумать |

Черновики лежат в `logs/vk_drafts.json` (`logs/` в `.gitignore`): запись через
`.tmp` + `os.replace`, статусы `pending`, `published`, `rejected`. Один пост —
одна строка: повторный цикл мониторинга не плодит дубликаты, а ручная правка
файла не теряет историю решений.

### Карточка владельцу

В чат `ZARUBA_VK_CHAT_ID` уходит сообщение:

```
Черновик из ВКонтакте: Оповещение на сайт
Заголовок: Внимание! Перенос блока
Текст: Блок 3 переносится с 15:00 на 16:30 … Источник: https://vk.com/wall-185685166_243
Раздел: /schedule — Расписание
Оригинал: https://vk.com/wall-185685166_243
! В посте есть картинка — проверь детали глазами перед публикацией
Команды: «Опубликовать vk-243» / «Отклонить vk-243»
```

Кнопки — inline-клавиатура типа `callback` с `payload` `publish:vk-243` и
`reject:vk-243` (по одной в ряд: подпись с id должна читаться целиком). Команды
продублированы словами: если клавиатура не отрисуется, владелец наберёт
«Опубликовать vk-243» руками и получит тот же результат.

### Права: только чат владельца

Команды `опубликовать <id>`, `отклонить <id>`, `черновики` и их кнопки бот
принимает **только** из чата, чей `chat_id` совпадает с `ZARUBA_VK_CHAT_ID` или
`ZARUBA_MAX_ALERT_CHAT_ID`. Любому другому человеку бот отвечает на эти слова
как на обычный текст («Такого раздела я не знаю») и не меняет ни файл, ни
черновик. Ответа «нет прав» нет намеренно: он сообщил бы, что такие команды
существуют.

Секрет вебхука и токен бота доказывают, что событие пришло от платформы, но не
дают права менять сайт — поэтому проверка `chat_id` остаётся единственной
защитой и стоит на обоих путях: текстовом и `message_callback`.

### Публикация: шаги и откаты

| Шаг | Что происходит | Если не вышло |
|---|---|---|
| 1 | черновик ищется по id и обязан быть `pending` | «Черновик не найден» / «уже опубликован» |
| 2 | `git status --porcelain --untracked-files=no`: посторонних правок нет | «в рабочем дереве есть посторонние изменения: …», черновик остаётся `pending` |
| 3 | запись в `content/alerts.yaml` или в `content/editions/<год>.yaml` (список `media`) | битый YAML — сообщение в MAX, файл не тронут |
| 4 | `.venv\Scripts\python.exe -m zaruba.content check` | файл возвращается байт в байт, в MAX уходит последняя строка ошибки |
| 5 | `git add <файл>` → `git commit -m "chore(bot): публикация из VK vk-<id>"` → `git push origin main` | сбой коммита снимается `git reset`, сбой пуша — `reset --hard HEAD~1`; дерево остаётся прежним |
| 6 | черновик → `published`, ответ «Опубликовано! Сайт обновится через 30–40 секунд» | — |

Оповещение встаёт **первой** строкой и получает `status: send`, `urgent: true`;
у прежних срочных строк снимается `urgent`. Плашка на сайте одна
(`services/alerts.active_alert` берёт первую опубликованную срочную), поэтому
старое оповещение остаётся в файле как опубликованное, но перестаёт гореть.
Ручные черновики строк не трогаются.

Медиа пишется в файл выпуска `content/editions/<год>.yaml`, а не в overlay
`<год>.d/media.yaml`: overlay читается только при `ZARUBA_PREVIEW_ENABLED`
(`06-info-section.md` §6.25) и хранит демонстрационные строки, поэтому карточка
из overlay не появилась бы на публичном сайте вовсе.

Шапка-комментарий файла сохраняется: `yaml.safe_dump` комментарии не пишет,
поэтому блок `#` в начале читается отдельно и дописывается обратно.

### Что меняется в `.env`

| Переменная | Что это |
|---|---|
| `ZARUBA_VK_TOKEN` | включает мониторинг (§9.13) |
| `ZARUBA_VK_CHAT_ID` | чат владельца: карточки и команды публикации |
| `ZARUBA_MAX_ALERT_CHAT_ID` | второй допустимый чат владельца (дублируется в проверке прав) |

Отдельной настройки для черновиков нет: путь фиксирован —
`logs/vk_drafts.json`.

### Проверка руками

```powershell
python -m zaruba.vk_watch --once --dry-run   # что нового в ленте, без отправки
python -m zaruba.vk_watch --once             # карточки в MAX + logs/vk_drafts.json
Get-Content logs\vk_drafts.json -Encoding UTF8
```

В чате владельца: «черновики» — список, «Опубликовать vk-<id>» — публикация,
«Отклонить vk-<id>» — отказ. После публикации в `logs/max_bot.log` появляется
`черновик vk-… опубликован`, а в журнале GitHub Actions — сборка Pages.

### Чего конвейер не делает

- Не правит `updated_at`, цену, тайминг и номинации: он переносит только текст
  поста, а числа берутся из «Положения» и таблиц организаторов.
- Не копирует картинки: фото-афиша остаётся в VK, а владелец проверяет детали
  глазами (пометка в карточке).
- Не публикует без человека и не публикует дважды: `published`/`rejected`
  закрывают черновик навсегда.
- Не отправляет `git push` при грязном дереве: чужие правки в `main` уходят
  только через обычный ревью-цикл.
