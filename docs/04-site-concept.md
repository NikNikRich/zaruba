# 04. Сайт, который «взлетит»: концепция

> **Контекст.** Документ предполагает доступ к данным организатора («Положение»,
> цены, база заявок, бренд). Сценарий «сайт делает фанат, аудитория — зрители» —
> в `05-fan-interactive.md`; он актуальнее, если доступа к организатору нет.

## 4.1. Главный вывод

«ЗАРУБА» — **соревнование с заявками**, а не городская афиша. Поэтому сайт,
который повторяет афишу («дата, место, красивое видео, кнопка „купить билет“»),
не даст роста. Взлетает тот сайт, который **снимает трение в четырёх точках**:

1. **Понять** — за 20 секунд: что это, когда, для кого, сколько стоит.
2. **Заявиться** — за 90 секунд с телефона, без аккаунта и без переписки.
3. **Оплатить** — сразу, с чеком и понятным статусом.
4. **Выступить и забрать** — точное время выхода, результаты, диплом, фото.

Формула позиционирования: **«ЗАРУБА — пульт чемпионата»**. Не «сайт фестиваля»,
а рабочая система: participant-facing сайт + админка организатора + уведомления.

## 4.2. Какой сайт делать: три варианта

| Критерий (вес) | A. Лендинг на Tilda | B. Только VK + kassy (как сейчас) | C. Собственный event-сайт |
|---|---|---|---|
| Заявки и оплата (25 %) | 1 — формы есть, но без логики заявок | 2 — вручную, но привычно | **5** — визард, оплата, статусы |
| Кабинет тренера / массовые заявки (20 %) | 1 | 1 | **5** |
| Расписание и результаты (15 %) | 2 | 3 | **5** |
| SEO и находимость (15 %) | 2 — одна страница | 1 — соцсеть | **5** — кластер страниц |
| Скорость запуска (10 %) | 3 — 3 недели | 5 — уже работает | 3 — 3–5 недель |
| Стоимость владения (10 %) | 2 — подписка и лимиты | 5 — 0 ₽ | 3 — хостинг и поддержка |
| Данные и аналитика (5 %) | 2 | 1 | **5** |
| **Взвешенный итог (0–5)** | **1,65** | **2,35** | **4,60** |

*Считано как Σ(вес × оценка) по шкале 0–5; веса в сумме дают 100 %.*

**Рекомендация: C + B.** Сайт — хаб и система заявок; VK/Telegram — каналы
трафика и уведомлений; `kassy.ru` — витрина для тех, кто покупает билеты
«по-старому». Tilda годится только как временная заглушка на 2 недели, если
нужно закрыть анонс раньше.

## 4.3. Структура сайта (IA)

```
/                         Лендинг: даты, суть, 2 дня, CTA «Заявиться» / «Билеты»
/nominations              Сетка номинаций: фильтры (возраст, стиль, формат)
/nominations/{slug}       Страница номинации: правила, цена, хронометраж, музыка
/register                 Визард заявки (4 шага, автосохранение)
/register/coach           Массовая заявка тренера (таблица / CSV)
/tickets                  Зрительские билеты (онлайн, СБП) + абонемент на 2 дня
/cabinet                  Кабинет: заявки, оплаты, документы, «повторить заявку»
/schedule                 Расписание по дням и блокам + «моё выступление»
/results                  Результаты онлайн, фильтры, диплом PDF + QR
/judges                   Жюри, MC, мастер-классы
/venue                    Площадка, как добраться, парковка, проживание, кафе
/faq                      FAQ + отдельный блок «Родителям»
/partners                 Партнёры, медиакит
/media                    Фото/видео прошлых лет, aftermovie, трансляция
/blog                     SEO-статьи (кластер «танцы в Тюмени»)
/legal/{offer,privacy,rules}  Оферта, 152-ФЗ, правила и критерии судейства
/admin                    Админка: заявки, оплаты, расписание, результаты
```

Принцип: **каждая номинация = отдельная индексируемая страница**. Это и SEO,
и удобство для человека, которому скинули ссылку «нам вот сюда».

## 4.6. Дизайн: «улица, а не детский утренник»

- **Визуальный код**: тёмный фон (графит/чёрный), один кислотный акцент
  (лайм, электрик или фуксия), крупная плотная типографика, диагонали и бегущие
  строки — как в баттл-афишах. Но: контраст текста ≥ 4.5:1, никаких «текст на видео».
- **Медиа**: 1 hero-видео 6–10 с (muted, autoplay, постер), дальше — сетка
  вертикальных клипов выступлений (это же готовый контент из Reels/Shorts).
- **Тон голоса**: короткие фразы, «ты», глаголы: «Заявись», «Зарубись»,
  «Покажи, на что способен». Без канцелярита и без «уважаемые участники».
- **Доверие**: фото зала, состав жюри, цифры прошлых лет, отзывы тренеров,
  прозрачные цены и правила.
- **Производительность как часть дизайна**: LCP < 2.5 с на 4G, вес первого
  экрана ≤ 300 КБ, изображения в AVIF/WebP, шрифты локально, JS — минимум
  (HTMX вместо SPA). Мобильный Lighthouse ≥ 90.
- **Доступность**: фокус-стили, alt-тексты, размер кнопок ≥ 44 px,
  формы с подписями (а не только placeholder).

## 4.7. Технологии и интеграции

Стек совпадает с уже принятым в прежнем проекте (`FastAPI + Jinja2 + HTMX`,
SQLAlchemy/Alembic, argon2, pyjwt, qrcode, reportlab) — не нужно вводить новый
фреймворк и новые практики. Код при этом **не переиспользуется**: здесь свой
пакет `src/zaruba/` и своя БД.

| Слой | Решение |
|---|---|
| Backend | FastAPI (async), Jinja2, HTMX-партиалы |
| БД | PostgreSQL 16 + Alembic-миграции |
| Файлы | локальный том в MVP → S3-совместимое хранилище (музыка, фото, дипломы) |
| Аутентификация | Telegram Login / VK ID + JWT-сессии (argon2 для паролей админов) |
| Оплата | ЮKassa или Т-Банк: СБП, карта, счёт для студии; вебхук → статус заявки; чек по 54-ФЗ |
| Уведомления | Telegram Bot API (заявка, оплата, «ваш выход через 30 мин»), e-mail — резерв |
| Документы | дипломы PDF (`reportlab`) + QR-проверка (`qrcode`), сертификаты участника |
| Аналитика | Яндекс.Метрика (цели: заявка, оплата), серверные события, UTM для VK/Telegram |
| Инфраструктура | Docker + reverse-proxy, HTTPS, бэкап БД, Sentry/логи, rate-limit на формы |
| SEO | SSR-страницы, `schema.org/Event`, sitemap.xml, Open Graph/og-image карточки |

Почему не SPA: формы и SEO — серверные задачи, а HTMX даёт «живой» визард без
200 КБ JS и без потери индексации.

## 4.8. Модель данных (минимум)

```
events(id, year, title, starts_at, ends_at, venue_id, status)
venues(id, name, address, capacity, map_url)
nominations(id, event_id, slug, track, format, style, age_from, age_to,
            price, duration_limit, rules_md, capacity)
applications(id, event_id, nomination_id, coach_id, team_name, status,
             total_amount, created_at)      -- draft→submitted→paid→confirmed
participants(id, application_id, full_name, birth_date, city, studio,
             parent_consent_at, music_file_id)
payments(id, application_id, provider_id, amount, status, receipt_url, paid_at)
slots(id, nomination_id, starts_at, stage, order_no)     -- расписание
results(id, participant_id, nomination_id, place, scores_json, diploma_file_id)
users(id, role, phone, telegram_id)        -- admin | coach | participant
media(id, event_id, kind, url, caption)
```

Правила: заявка создаётся как `draft` (не теряется), оплата меняет статус
идемпотентно (по `provider_id`), диплом генерируется один раз и кэшируется,
данные детей минимизированы и не публикуются без согласия.

## 4.9. SEO и контент: как сайт начнёт находить сам

| Кластер | Примеры | Страница |
|---|---|---|
| Событие | «заруба тюмень», «танцевальный чемпионат тюмень 2026» | `/` |
| Номинации | «хип-хоп соло чемпионат тюмень», «high heels баттл тюмень» | `/nominations/{slug}` |
| Участие | «как участвовать в чемпионате», «взнос за номинацию» | `/faq`, `/nominations` |
| Родителям | «куда отдать ребёнка на танцы в Тюмени» | `/blog/*` |
| Результаты | «заруба 2025 результаты», «победители чемпионата танцы» | `/results` |
| Площадка | «золотые ворота сибири афиша», «зал для танцев Тюмень» | `/venue` |

**12 стартовых SEO-страниц:** главная, 6 номинаций (по 2 на трек), жюри,
площадка, FAQ, медиа, результаты + 2 статьи в блог. Затем по статье в месяц:
«Как выбрать первые соревнования для ребёнка», «Что надеть на хип-хоп
чемпионат», «Heels на сцене: с чего начать».

Обязательно: `schema.org/Event` с датами и местом, микроразметка FAQ,
title/description, быстрые страницы, ссылки со студий-партнёров, карточки
в Яндекс.Бизнес и Google Business Profile.

## 4.10. План работ: 3 спринта до продаж

| Спринт | Результат | Оценка |
|---|---|---|
| **1. Каркас и заявки** | Лендинг, `/nominations`, визард без оплаты, админка заявок, аналитика | 5–7 дней |
| **2. Деньги и тренеры** | Оплата + вебхук + чек, кабинет тренера, CSV-импорт, Telegram-уведомления | 5–7 дней |
| **3. После события** | Расписание, результаты, дипломы PDF/QR, медиа, SEO-кластер, og-карточки | 5–7 дней |

Итого MVP — **3–4 недели** одним разработчиком при готовом контенте.
Критический путь — не код, а **«Положение», цены и медиа от организаторов**.

## 4.12. Риски и юридика

| Риск | Что делать |
|---|---|
| Организатор не даёт «Положение» и цены | Зафиксировать сроки контента в договоре; до этого — прототип на демо-данных |
| VK — единственный канал | Дублировать в Telegram, собирать телефон/e-mail в базе заявок |
| Персональные данные детей (152-ФЗ) | Согласие родителя в визарде, шифрование, минимизация, политика обработки, сроки хранения |
| Оплаты и возвраты | Публичная оферта, правила возврата, явные статусы заявок |
| Музыкальные права (РАО/ВОИС) | Договор на публичное исполнение фонограмм до события |
| Перегрузка расписания | Лимиты по номинациям (`capacity`), авто-лист ожидания |
| Спам и «мусорные» заявки | Rate-limit, Яндекс SmartCaptcha, подтверждение по телефону |
| Падение сайта в дни события | Кэш статики, CDN, отдельная лёгкая страница `/schedule` |

## 4.13. Первые 7 дней

1. Созвон с организатором: цены, номинации, даты, доступ к VK и медиа.
2. Купить домен (`zaruba72.ru` не делегирован на 2026-10-23 — проверить у
   регистратора) и связать его с VK-группой как основной цифровой контур;
   настроить почту.
3. Собрать контент-минимум: логотип, 5 фото, 1 видео, состав жюри, текст «о событии».
4. Свёрстать лендинг + 3 страницы номинаций на демо-данных, показать организатору.
5. Подключить Метрику и цель «Заявка», запустить тест-лендинг в VK на 3–5 дней.
6. По результатам теста зафиксировать сетку номинаций и цены, стартовать спринт 2.

## 4.14. Что именно сделает сайт «взлетевшим» (короткий ответ)

Не эффекты, а **три вещи одновременно**:

1. **Скорость заявки** — 90 секунд с телефона, без аккаунта и переписки
   (это даёт больше заявок, чем любой редизайн).
2. **Кабинет тренера** — превращает одного лояльного тренера в 20–40 заявок.
3. **Жизнь после события** — результаты, дипломы, фото и видео, которые
